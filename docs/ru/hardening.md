# Ужесточение и некорректный ввод

> **Статус:** реализовано в M7 для релиза 0.1.0.

Nvox разбирает враждебные файлы во время CTF и реагирования на инциденты.
Цель — не сделать Python песочницей, а не дать некорректному вводу выйти за
границы обработки ошибок плагинов, исчерпать память или незаметно развернуть
бомбу распаковки.

## Ограничения распаковки

`generic.archive` применяет независимые лимиты до и после распаковки:

| Параметр | По умолчанию | Действие |
|---|---:|---|
| `max_entries` | 256 | Максимум проверяемых записей |
| `max_file_bytes` | 32 MiB | Предел объявленного и фактического размера |
| `max_total_bytes` | 96 MiB | Суммарный объём распаковки |
| `max_ratio` | 1000 | Максимальный коэффициент расширения |

Для ZIP проверяются объявленный размер и коэффициент до чтения. Чтение
ограничено `max_file_bytes + 1`, затем коэффициент проверяется по фактическим
байтам — поддельный центральный каталог не обходит лимит. gzip, bzip2 и xz
используют ограниченные распаковщики и ту же проверку. Рекурсия ограничена
`scan.max_depth`, `scan.max_artifact_bytes` и бюджетами архива.

Пропущенная запись попадает в `archive/summary` с причиной. Скан продолжается,
остальные плагины работают.

```toml
[plugins.options."generic.archive"]
max_entries = 128
max_file_bytes = 8388608
max_total_bytes = 33554432
max_ratio = 500
```

Другие парсеры также используют ограниченные смещения и размеры выхода.
PDF ограничен `generic.pdf.max_stream_bytes`; PNG/TIFF/JPEG/GIF ограничивают
текст и чанки; артефакты сверх `scan.max_artifact_bytes` отклоняются.

## Изоляция процессов

По умолчанию Python-плагины работают в потоках с кооперативным дедлайном.
Блокирующий вызов в C нельзя прервать. Включите изоляцию для недоверенных
локальных Python-плагинов:

```toml
[scan]
isolation = "process"
```

Или для одного скана:

```bash
nvox scan challenge.bin --isolation process
```

Подходящие плагины заново обнаруживаются в дочернем процессе и запускаются с
протоколом результатов через pipe. Родитель убивает процесс по тайм-ауту.
Артефакты сериализуются обратно с сохранением происхождения.

Ограничения:

- подходят встроенные плагины, плагины из каталогов и entry points;
- плагины, зарегистрированные вручную, и командные/мостовые плагины остаются в
  потоке или песочнице;
- каждый вызов платит за запуск процесса, поэтому потоковый режим остаётся по
  умолчанию;
- изоляция процессов не является ОС-песочницей: она не ограничивает файлы и
  сеть. Для враждебного кода используйте контейнер, VM или ОС-песочницу.

В обоих режимах тайм-аут становится пропуском `timeout` и не прерывает скан.

## Корпус фаззинга

`tests/fuzz_targets.py` содержит детерминированные входы для PNG, JPEG, GIF,
BMP, WAV, DTMF, ZIP, TAR, gzip, PDF, OOXML, пустого и обрезанных файлов.
Каждый вход запускается без изменений и с мутациями: инверсия битов,
усечение, удаление, вставка, нулевые блоки и мусор в конце.

Короткий проход в pytest:

```bash
uv run pytest tests/test_fuzz_corpus.py
```

Длинный проход перед релизом:

```bash
uv run python scripts/fuzz-parsers.py --iterations 200
```

Ошибка означает, что ввод вышел за границу обработки ошибок движка вместо
обычного пропуска или ошибки парсера. Релизный чек-лист требует зелёный
короткий проход; длинный рекомендуется перед тегом.

## Внешние инструменты

Мосты и командные плагины остаются необязательными. Отсутствие бинарника даёт
пропуск `requirement`, а не сбой. Команды выполняются через ограниченную
песочницу из [Плагины](plugins.md).
