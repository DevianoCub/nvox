# Производительность и решение об ускорителе

> **Статус:** бенчмарк M7 для 0.1.0.

Nvox отдаёт приоритет переносимому ядру на стандартной библиотеке, а не
нативному расширению. Здесь записаны повторяемый бенчмарк и решение не
добавлять Rust/PyO3-ускоритель в 0.1.0.

## Методика

`scripts/benchmark.py` создаёт четыре детерминированных входа и запускает
полный граф встроенных плагинов с глубиной 3 и одним потоком:

- `text-64k` — 64 KiB ASCII;
- `entropy-1m` — 1 MiB детерминированных байтов высокой энтропии;
- `png-256` — RGB PNG 256x256;
- `zip-8` — ZIP с восемью небольшими текстовыми файлами.

Первый проход прогревает импорты и кэши; берётся медиана следующих запусков.
Внешние инструменты отключены.

```bash
uv run python scripts/benchmark.py --repeat 3
uv run python scripts/benchmark.py --repeat 3 --json
```

## Референсные результаты

Linux 7.3.0 x86_64, Python 3.14.8, один поток:

| Сценарий | Вход | Медиана | Пропускная способность | Артефакты |
|---|---:|---:|---:|---:|
| `text-64k` | 64 KiB | 0.247 с | 0.25 MiB/s | 69 |
| `entropy-1m` | 1 MiB | 1.432 с | 0.70 MiB/s | 50 |
| `png-256` | 2.2 KiB | 0.809 с | — | 121 |
| `zip-8` | 1.1 KiB | 0.165 с | — | 247 |

Для маленьких структурированных входов пропускная способность не показательна:
стоимость определяется диспетчеризацией плагинов, созданием артефактов,
спекулятивными декодерами и повторным анализом производных артефактов. Числа —
базовая линия регрессий, а не обещание для другого оборудования.

## Решение

**Без Rust/PyO3-ускорителя в 0.1.0.**

1. Измеренный горячий путь — широкий граф небольших Python-плагинов, а не один
   изолированный цикл по пикселям или байтам. Нативное расширение не уберёт
   диспетчеризацию, хранилище и происхождение.
2. Дорогие необязательные пути уже ограничены `max_pixels`, `max_planes`,
   `max_offsets`, лимитами архивов и тайм-аутами.
3. Нативный артефакт усложнил бы установку релиза, который сейчас работает на
   чистом Python с двумя небольшими зависимостями.
4. Нет доказательств выигрыша на порядок для типичных CTF-входов.

Решение пересматривается, если профиль покажет один конкретный pure-Python
парсер, доминирующий после применения бюджетов. Будущий ускоритель должен быть
необязательным wheel, а не обязательной зависимостью.

## Настройка

- `scan.max_depth`, `scan.timeout`, `scan.max_artifact_bytes`, `scan.jobs`;
- `image.lsb.max_pixels`, `max_planes`, `bits`;
- `image.channels.max_pixels`, `emit_filters`, `max_filters`;
- `generic.carve.max_scan_offset`, `max_carved`;
- `decoder.deflate.max_input_bytes`, `max_offsets`;
- `generic.archive.max_entries`, `max_file_bytes`, `max_total_bytes`,
  `max_ratio`.

```bash
time nvox scan large.png -f 'ctf{}' --no-external --out /tmp/nvox-bench
```
