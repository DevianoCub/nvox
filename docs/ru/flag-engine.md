# Движок флагов

> **Статус:** 0.1.0. Поддерживаются поверхности сырых байтов, строк,
> метаданных и битовых потоков, а также встроенная цепочка декодеров.
> HTML-отчёт и TUI доступны с M4.

Движок флагов принимает пользовательские форматы и ищет по всем поверхностям,
которые может создать Nvox. Именно поэтому существует граф артефактов: флаг,
видимый только после `LSB -> zlib -> base64`, остаётся обычным совпадением.

## Синтаксис форматов

Формат — литерал с ровно одним `{}`. Скобки входят в синтаксис флага, поэтому
`ctf{}` соответствует `ctf{...}`:

| Формат | Совпадение |
|---|---|
| `ctf{}` | `ctf{...}` |
| `htb{}` | `htb{...}` |
| `pico{}` | `pico{...}` |
| `flag{}` | `flag{...}` |

Текст вне `{}` экранируется буквально. `HTB{}` не совпадёт с `htb{...}` без
`-i`. Тело непустое и не пересекает перевод строки; длина по умолчанию от 4 до
200 символов (`--min-length`, `--max-length`).

```bash
nvox scan evidence/ --flag-format 'ctf{}' --flag-format 'htb{}' --flag-format 'pico{}'
```

Для произвольных шаблонов используйте `--flag`:

```bash
nvox scan dump.bin --flag 'FLAG\{[A-Za-z0-9_]{8,64}\}' -i
```

Сырые шаблоны компилируются для поиска по байтам; конструкции Unicode, которые
нельзя закодировать в байты, отклоняются. Каждый формат компилируется отдельно,
поэтому метка формата сохраняется в находке. Совпадающие значения
дедуплицируются.

## Поверхности

| Поверхность | Реализация |
|---|---|
| Сырые байты | Полный payload артефакта в памяти |
| Строки | ASCII и UTF-16LE/BE с абсолютными смещениями |
| Текстовые артефакты | Все `text`-артефакты анализаторов и декодеров |
| Метаданные | JSON-метаданные, EXIF, XMP, IPTC, ICC, текст чанков |
| Битовые потоки | Битовые плоскости PNG и артефакты анализа каналов |
| Декодированные слои | Выход цепочки декодеров, рекурсивно |

## Цепочка декодеров

Встроенные декодеры: `base64`, `base64url`, `base32`, `base85`, `hex`, `url`,
`rot13`, `rot47`, `reverse`, `gzip`, `zlib`, `bzip2`, `xz`, `deflate`
(сырой и встроенный zlib), перебор однобайтового `xor`.

Декодеры — обычные плагины, поэтому каждый слой хешируется и возвращается в
граф. Движок применяет их в ширину с:

- бюджетом глубины (`scan.max_depth`, по умолчанию 4);
- ключами посещения и хранением по содержимому — циклы завершаются;
- эвристиками: base-кодировки должны валидироваться и давать осмысленный
  текст или сигнатуру; распаковка требует магию контейнера;
- ограничением размера выхода (`scan.max_artifact_bytes`);
- тайм-аутом вызова и общим бюджетом запусков.

Неудачные попытки записываются как пропуски с причиной; смотрите
`nvox scan --verbose`.

## Перебор XOR

Для байтовых артефактов до 16 KiB по умолчанию перебираются 255 ненулевых
однобайтовых ключей, результаты оцениваются, лучшие становятся текстовыми
артефактами. Оценка учитывает печатный текст, буквы/цифры, парные скобки и
ключевые слова CTF.

```toml
[plugins.options."decoder.xor"]
max_input_bytes = 16384
max_candidates = 5
min_printable = 0.75
```

Отключение: `--no-xor-brute`.

## Находки

```json
{
  "value": "lsb_1s_fun",
  "format": "ctf{}",
  "surface": "bitstream",
  "offset": 128,
  "artifact": "5f0c…",
  "confidence": "medium",
  "chain": [
    {"plugin": "image.lsb", "name": "lsb/channel=1", "sha256": "5f0c…"}
  ],
  "evidence": {"sha256": "…", "path": "photo.png"}
}
```

- `offset` — смещение в артефакте, где найдено совпадение, а не в исходном
  доказательстве. Цепочка объясняет путь.
- `chain` — путь происхождения от доказательства; прямое совпадение имеет
  пустую цепочку.
- `artifact` — SHA-256 артефакта с совпадением; `nvox extract <sha256>`
  записывает его на диск.
- `confidence` зависит от поверхности: `high` для текста/метаданных, `medium`
  для строк, битовых потоков и кандидатов XOR, `low` для прямого совпадения в
  сырых байтах. При нескольких цепочках выбирается кратчайшая и более
  уверенная.

## Ложные срабатывания

Для шаблонов вроде `flag{}`:

- требуйте минимальную длину тела (по умолчанию 4);
- предпочитайте структурированные поверхности и короткие цепочки;
- используйте хуки `on_finding` для изменения или удаления совпадений;
- сохраняйте уникальные значения, но сообщайте одно лучшее вхождение на файл.

## CLI

```bash
nvox scan photo.png --flag-format 'ctf{}'
nvox scan ./dump --flag 'flag\{[^}]+\}' -i --min-length 8
nvox scan image.png --flag-format 'htb{}' --no-xor-brute --out out/
nvox scan image.png --flag-format 'pico{}' --json
```

Код `2` означает, что найден хотя бы один флаг. `findings.json` пишется в
`--out` даже без `--json`.
