# Архитектура

## Общая схема

```
доказательство -> снимок только для чтения -> SHA-256 + MIME
                                      |
                                      v
                         хранилище артефактов (SHA-256)
                                      |
                                      v
                     очередь артефактов -> реестр плагинов
                                      |
                    анализаторы | извлекатели | декодеры
                    Python-плагины | TOML-команды
                                      |
                                      v
                    движок флагов -> находки + происхождение
                                      |
                                      v
                         JSON/CSV, HTML-отчёт, TUI
```

Цикл важен: анализатор, породивший артефакт, возвращает его в ту же очередь.
Поэтому цепочка `PNG -> LSB -> zlib -> base64 -> флаг` не требует специального
кода.

## Компоненты

| Модуль | Назначение |
|---|---|
| `core/evidence.py` | неизменяемый снимок входа, хеш, определение MIME |
| `core/store.py` | хранилище артефактов с ограничением размера |
| `core/registry.py` | обнаружение и проверка плагинов |
| `core/engine.py` | очередь, лимиты, дедупликация, хуки |
| `core/isolation.py` | необязательный запуск Python-плагинов в дочернем процессе |
| `core/flags.py` | форматы флагов, регулярные выражения, поверхности поиска |
| `core/findings.py` | находки, уверенность, кратчайшие цепочки происхождения |
| `core/sandbox.py` | ограниченный запуск внешних команд |
| `plugins/*` | встроенные пакеты анализа |

Плагины не пишут на диск и не меняют доказательства. Они получают `Artifact` и
`Context`, а все результаты проходят через хранилище и движок.

## Планирование и лимиты

- **Глубина** (`scan.max_depth`, по умолчанию 4): число шагов от исходного
  доказательства. Корневой артефакт имеет глубину 0.
- **Тайм-аут** (`scan.timeout`, 120 с): на один запуск плагина. По умолчанию
  Python-плагины работают в потоках и проверяют кооперативный дедлайн при
  отправке артефактов. Зависший плагин отбрасывается, поздние результаты
  игнорируются. Внешние команды и мосты дополнительно получают жёсткий
  тайм-аут подпроцесса и завершение группы процессов. С
  `scan.isolation = "process"` подходящие Python-плагины запускаются в
  дочернем процессе и уничтожаются по тайм-ауту.
- **Размер** (`scan.max_artifact_bytes`): предел материализуемого артефакта;
  превышение становится пропуском.
- **Потоки** (`scan.jobs`, 0 = авто): число одновременных вызовов плагинов.
  Очередь артефактов обходится детерминированно в ширину.
- **Дедупликация**: `(хеш артефакта, имя плагина, JSON опций)` для
  планирования и SHA-256 для хранения.
- **Поверхности**: сырые байты, текстовые артефакты, метаданные, строки
  ASCII/UTF-16/UTF-32 и битовые потоки PNG.

## Хуки

| Хук | Когда | Назначение |
|---|---|---|
| `pre_ingest(path)` | до хеширования | отклонить вход, вернув причину |
| `on_artifact(artifact, ctx)` | артефакт сохранён | добавить анализ или артефакты |
| `post_scan(result)` | очередь пуста | агрегировать, переранжировать, экспортировать |
| `on_finding(finding)` | найдено совпадение | подавить ложное срабатывание или изменить находку |

Исключение в хуке изолируется и записывается как пропуск `hook`.

## Почему Python

Python даёт максимально быстрый путь к широкому покрытию: Pillow/numpy для
пикселей, богатая экосистема парсеров и плагины в несколько строк. Бенчмарк
0.1.0 не обосновал Rust/PyO3-ускоритель: затраты распределены между
диспетчеризацией плагинов, созданием артефактов и спекулятивными декодерами, а
не сосредоточены в одном цикле обработки пикселей. Решение и базовые числа
записаны в [Производительность](performance.md). Внешние бинарники
рассматриваются как необязательные ускорители, а не как определение функции.

## Точки расширения

1. Встроенные пакеты: `src/nvox/plugins/{generic,decoders,image,audio,bridges}`.
2. Локальные каталоги: `./plugins`, `~/.config/nvox/plugins`.
3. Пакеты с entry point `nvox.plugins`.
4. Декларативные TOML-плагины, оборачивающие команду.
5. Хуки в плагинах.

Стабильность API определяется `nvox.api.API_VERSION` (сейчас `1`). Ломающие
изменения увеличивают версию API, плагины объявляют целевую версию.
