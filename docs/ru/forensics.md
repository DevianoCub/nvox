# Криминалистика и работа с доказательствами

> **Статус:** приём доказательств, хеширование, хранилище артефактов, JSON,
> HTML-отчёт и русский перевод реализованы в 0.1.0. Ограничения и изоляция
> процессов описаны в [Ужесточение](hardening.md).

Nvox — инструмент триажа и CTF, а не сертифицированный криминалистический
комплекс. Его результат должен объясняться и воспроизводиться.

## Принципы

1. **Доказательства неизменяемы.** Входные файлы открываются только для
   чтения; Nvox не переименовывает, не перемещает и не пишет рядом с ними.
2. **Всё хешируется.** До анализа фиксируются SHA-256, размер и MIME. Payload
   захватывается один раз, поэтому изменение файла на диске во время скана не
   влияет на результат.
3. **Результаты воспроизводимы.** `findings.json` содержит версию Nvox,
   форматы, опции, хеши доказательств, пропуски и цепочки происхождения.
4. **Происхождение обязательно.** Каждая находка несёт цепочку плагинов и
   параметров.
5. **Нет скрытого сетевого доступа.** Анализ локальный; плагины не должны
   использовать сеть по умолчанию.
6. **Ограниченные и объяснимые пропуски.** Глубина, время и размер
   ограничены; всё пропущенное перечислено с причиной.

## Структура вывода

```
out/
  artifacts/
    <xx>/<sha256>
  index.jsonl
  findings.json
```

`findings.json` — источник истины для запуска:

- `formats`, `patterns`, `options` описывают, что искали;
- каждая запись доказательства содержит путь, SHA-256, размер, MIME,
  артефакты и пропуски;
- каждая находка ссылается на доказательство и артефакт и содержит цепочку
  первого родителя;
- `summary` считает файлы, артефакты, находки, пропуски и запуски плагинов.

HTML-отчёт (`report.html`) и `nvox report` доступны с M4.

## Метаданные запуска

```json
{
  "nvox": "0.1.0",
  "started_at": "2026-11-14T12:00:00Z",
  "finished_at": "2026-11-14T12:00:06Z",
  "formats": ["ctf{}"],
  "patterns": [],
  "options": {"ignore_case": false, "min_length": 4, "max_length": 200},
  "summary": {"files": 1, "artifacts": 42, "findings": 1, "skips": 7}
}
```

Хеш доказательства повторяется в каждой находке, поэтому её можно однозначно
связать с входом.

## Ограничения безопасности

| Риск | Контроль |
|---|---|
| Zip-бомбы и бомбы распаковки | лимиты записей, файла, суммы и коэффициента; пределы декодеров и артефактов; глубина |
| Бесконечные цепочки плагинов | дедупликация по хешу, посещённые ключи, `max_depth` |
| Зависшие плагины | кооперативный тайм-аут; жёсткое убийство группы процессов для команд и мостов |
| Потоки вывода | предел артефакта; ограничение stdout/stderr и файлов для команд |
| Случайное изменение | чтение только для чтения, отдельный вывод, без записи на месте |
| Враждебные парсеры | ограниченные stdlib-парсеры; детерминированный корпус; необязательная изоляция процессов |

Кооперативный тайм-аут бросает поток, но не останавливает Python-код, который
игнорирует дедлайн. `scan.isolation = "process"` убивает подходящий
Python-плагин по тайм-ауту, но не ограничивает файловую систему и сеть. Для
враждебного кода используйте ОС-песочницу. См. [Ужесточение](hardening.md).

## Как публиковать результаты

Укажите SHA-256 доказательств и метаданные запуска из `findings.json`,
цепочку происхождения каждой находки, список пропусков и причин
(`--verbose`, а также JSON) и точную командную строку. Этого достаточно для
воспроизведения при наличии того же входа.

## Этика

Используйте Nvox только для файлов, которыми владеете или которые разрешено
исследовать. Анализ чужих приватных файлов и эксфильтрация данных не входят в
область проекта.
